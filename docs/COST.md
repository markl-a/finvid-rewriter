## 2. 本片一次完整執行的估算與實際

素材 15 分 50 秒（950 秒）。

實際帳本（[data/demo/manifest.json](../data/demo/manifest.json)）：

| 步驟 | 實際用量 | 實際花費 |
|---|---|---|
| s1 下載+前處理 | 950 s → 948 s（去靜音只省 0.2%，見下方說明） | $0 |
| s2 STT `gpt-4o-mini-transcribe` | 15.81 分鐘，2 個分段 | $0.0474 |
| s3 Pass A `gpt-5-mini` | 4,354 in / 3,271 out（含推理 token） | $0.0076 |
| s3 Pass B `gpt-5` × 3 | 每段約 1,230 in / 1,620 out（含推理 token） | $0.0533 |
| s4 TTS edge-tts | 381 字元 | $0 |
| s4 AI 畫面 ComfyUI/LTX-Video | 3 支 × 2 段 × 5 秒，共 534 秒 GPU | $0 |
| **合計** | | **$0.099**（最新一次 Pass A 命中快取，只付 Pass B $0.052） |

估算 vs 實際的落差：第一版 dry-run 估 $0.083，主要低估了 gpt-5 系列的推理 token 會計入輸出。
已把估算常數校準到實測值（`PASS_A_OUTPUT_TOKENS`、`PASS_B_OUTPUT_TOKENS`），現在 dry-run 估 $0.107。

### 開發迭代的總花費（快取的價值）

第 3 步的閘門與提示詞改了 4 版（重複判斷、時間格式、數字格式）。每次重跑只付第 3 步的錢，第 1、2 步全部 cache hit：

| 執行 | 重做 | 快取 | 花費 |
|---|---|---|---|
| 1 | s2 | s1 | $0.047 |
| 2–5 | s3 × 4 版 | s1, s2 | $0.045 + $0.067 + $0.052 + $0.061 |
| 6–7 | s4 × 2 版 | s1, s2, s3 | $0 |
| **整個開發過程** | | | **$0.27**（無快取會是 4 × $0.11 + 2 × $0.11 ≈ $0.65） |

### 對照：不做成本控制會花多少

| 情境 | 估算 |
|---|---|
| 整支送 `whisper-1` 而非 mini | 15.8 min × $0.006 = $0.095（貴 2 倍） |
| 不篩選，8 段全用 `gpt-5` 寫腳本 | 8 × $0.0178 = $0.142（Pass B 貴 2.7 倍） |
| 3 支共 118 秒用 AI 影片 API 生成 | 118 s × $0.25 = **$29.5** |
| 8 段全生成 AI 影片 | ≈ **$79** |
| 同一支影片被重跑 5 次（無快取） | 5 × $0.108 = $0.54，有快取 = $0.108 |

結論：最大的一筆是影片生成，其次是強模型寫腳本。所以流程把「要不要生成」的判斷放在最前面（Pass A 打分 + 篩選閘），把生成本身換成零成本的程式化合成，並把 AI 影片 API 當可選項而非預設。

## 3. 每個決策的取捨

### 為什麼只拉音軌、去靜音，但不預設加速
- 只拉音軌：影片檔 50–100 MB vs 音軌 15 MB，下載時間與磁碟都省，STT 本來就不吃畫面。
- 去靜音：對純談話素材有效，對準確率幾乎無影響。**但本片實測只省 0.2%**：用 ffmpeg `volumedetect` 量到平均 −22.5 dB，全程有音樂床；要切到 14 秒以上得把門檻拉到 −22 dB，那會連人聲一起切。所以門檻留在安全的 −35 dB / 0.7 s，並在文件誠實記錄它對這支影片沒用。dry-run 估算裡的「省 8%」是談話節目的通用假設，對本片偏樂觀。
- 加速 1.2×：Whisper 系列在 1.2× 內中文準確率仍可接受，但會多錯字；demo 不值得為省 $0.008 冒風險。做成 `FINVID_SPEEDUP` 開關並在文件說明，比硬開更符合「合理判斷」。

### 為什麼 STT 預設走雲端而不是本機
- 本機 faster-whisper 是 $0，但第一次要下載模型、CPU 跑幾分鐘，評審機器不一定有 GPU。
- `gpt-4o-mini-transcribe` 整支 $0.04，用同一把 OpenAI key，安裝成本最低。
- 兩者都實作，`FINVID_STT_PROVIDER=local` 一行切換。

### 為什麼兩階段而不是一次叫強模型做完
- 逐字稿約 7k tokens，強模型讀一次 ≈ $0.01，便宜模型 ≈ $0.002。差 5 倍。
- 更重要的是「先知道哪幾段值得做」才能決定 Pass B 呼叫幾次。一次做完等於每段都付強模型的錢。
- 篩選閘是純程式，$0，而且規則可解釋（分數、重複、上限），評審看 `03_scripts.json` 就知道每段為什麼被跳過。

### 為什麼 Pass B 用 `gpt-5` 而不省
- 改寫品質決定兩件事：合不合法（反抄襲閘過不過）、值不值得看。
- 只對 3 段呼叫，實際總共 $0.053（每段約 $0.018，其中六成是推理 token）。換 `gpt-4.1-mini` 每段約 $0.003，省 $0.045，但退回重寫的機率上升；三次實跑反抄襲閘全部一次通過（重疊率 0%），這個品質值得。
- 用 reasoning effort = low：改寫不需要長推理。

### 為什麼反抄襲閘用 n-gram 而不是再叫一次 LLM 判斷
- $0、確定性、可寫測試。
- 6 字元 n-gram：中文 6 字連續相同已經很難是巧合；數字與專有名詞（台北市、2.5%）短於 6 字不會誤判。
- 15% 重疊 + 最長 12 字：實測改寫良好的腳本落在 3–8%，照抄的超過 50%。
- 超標退回一次就停：第二次還抄代表模型對這段做不到，繼續重試是浪費。

### 影片生成：固定每支 2 段 5 秒鏡頭迴圈，而且用本機
- brief 說「生成短影音通常是最貴的一步」——整支 40 秒逐句用雲端 API 生成是每支 $2–10。財經數據型內容的價值在數字與圖表，所以生成用量鎖定：每支 clip 2 段 5 秒（開場 + 正文各一），正放+倒放迴圈鋪滿整支；圖表用 matplotlib 重繪後疊在畫面上（$0、可控、天然符合「圖表自製」），字幕／旁白／出處用 PIL + edge-tts + ffmpeg。
- 生成的閘門跟寫腳本一樣：只給通過篩選與反抄襲閘的 clip、每支固定段數、預算閘、依 (provider, model, workflow, prompt) hash 快取（換版面重渲染時 6 段全部命中，33 秒完成）。
- 兩個免費 provider：HF ZeroGPU（雲端、25 秒/段、每日額度）與本機 ComfyUI（80–120 秒/段、無上限），同一個開源 LTX-Video 模型，`hf,comfy` 先花免費額度再用本機。帳本以 `gpu_second` 記錄，跟雲端方案（MiniMax $0.08–0.27/段、Kling $0.18–0.42/段、Veo $0.15–0.40/秒）放在同一張表比較：本機是「用時間換錢」，對 demo 與小量產出划算，量大時雲端每段 20 秒的吞吐才有意義。
- 帳本仍記一筆「整支都用 AI 影片 API」的 reference 費用（3 支約 $27.5），讓省下的量可見。
- 第三個 $0 選項是真實素材：`FINVID_BROLL=pexels` 每句台詞從 Pexels 拉一段直式實拍素材（查詢字串就是 Pass B 已寫好的 `visual`，不多叫 LLM），可商用免署名；貴的不是錢而是額度（每小時 200 次搜尋），所以搜尋結果與下載都快取在 `data/_broll/` 跨影片共用，重跑 0 次呼叫。跟 AI 鏡頭可以並用：hook 用唯一一段 AI 鏡頭，其餘全實拍，GPU 時間從每支 2 段降到 1 段。

### 冪等快取的粒度
- 以 stage 為單位，key = 影響輸出的設定 hash。改 Pass B 的模型只重做 s3、s4，不重做 STT。
- 輸出檔不在就視為未做，避免「manifest 說做過但檔案被刪」的假命中。
- 同一支影片在 web UI 同時只允許一個執行，避免並發重複計費。

## 4. 規模化時的成本

| 影片長度 | STT | LLM | 合成 | 每支 | 100 支/月 |
|---|---|---|---|---|---|
| 15 min | $0.05 | $0.06 | $0 | ≈ $0.11 | $11 |
| 60 min | $0.18 | $0.08（Pass A 較長，Pass B 不變） | $0 | ≈ $0.26 | $26 |
| 60 min，Pass B 改 `gpt-4.1-mini` | $0.18 | $0.03 | $0 | ≈ $0.21 | $21 |
| 60 min，STT 改本機 | $0 | $0.08 | $0 | ≈ $0.08 | $8 + 機器時間 |

規模化時先換的順序：STT 改本機（省最多、品質不掉）→ Pass B 降級（品質略降）→ 加速音檔（準確率略降）。
